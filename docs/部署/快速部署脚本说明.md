# 快速部署脚本说明

## 📋 概述

`deploy.sh` 和 `deploy.ps1` 是两个**快速部署脚本**，用于快速同步代码到服务器，**不支持版本管理和回滚**。

## 🎯 使用场景

### 适用场景
- ✅ **开发环境**：快速迭代和测试
- ✅ **测试环境**：功能验证
- ✅ **紧急修复**：需要快速部署小改动
- ✅ **单服务器部署**：不需要版本管理的小型项目

### 不适用场景
- ❌ **生产环境**：缺少版本管理和回滚能力
- ❌ **多版本管理需求**：无法保留历史版本
- ❌ **需要回滚能力**：部署失败无法快速恢复

## 📊 与版本化部署的对比

| 特性 | 快速部署脚本 | 版本化部署脚本 |
|------|------------|--------------|
| **版本管理** | ❌ 不支持 | ✅ 支持 |
| **回滚能力** | ❌ 不支持 | ✅ 支持 |
| **磁盘占用** | 较低（单版本） | 较高（多版本） |
| **部署速度** | ⚡ 较快（直接覆盖） | 🐢 较慢（创建版本目录） |
| **安全性** | ⚠️ 低（不可回滚） | ✅ 高（可回滚） |
| **适用场景** | 开发/测试环境 | 生产环境 |
| **部署目录** | `/opt/ImageClassifierBackend` | `/opt/ICBackend` |
| **虚拟环境** | 独立虚拟环境 | 共享虚拟环境 |

## 🔍 脚本详细分析

### deploy.sh (Linux/Mac)

**部署目录**：`/opt/ImageClassifierBackend`

**部署步骤**：
1. [1/5] 同步代码文件（app目录和重要文件）
2. [2/5] 检查配置文件（创建.env文件）
3. [3/5] 安装依赖（创建/更新虚拟环境）
4. [4/5] 重启服务
5. [5/5] 检查服务状态

**特点**：
- 直接覆盖现有代码
- 在部署目录下创建独立的虚拟环境
- 只处理 `.env` 配置文件
- 不复制 `prompts` 目录

### deploy.ps1 (Windows PowerShell)

**部署目录**：`/opt/ImageClassifierBackend`

**部署步骤**：与 `deploy.sh` 相同

**特点**：
- PowerShell 版本，适用于 Windows 环境
- 功能与 `deploy.sh` 完全一致
