# 自动测试说明

## 📋 概述

本文档详细说明 GitHub Actions 中自动测试的执行环境、流程和测试代码的组织方式。

## 🖥️ 测试运行环境

### 运行位置

测试运行在 **GitHub Actions 提供的虚拟机上**，不是在你的本地机器或服务器上。

```
┌─────────────────────────────────────────┐
│ GitHub Actions 虚拟机 (Ubuntu Latest)   │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │ 测试执行环境                     │   │
│  │                                 │   │
│  │ 1. 检出代码 (git checkout)      │   │
│  │ 2. 安装 Python 3.8              │   │
│  │ 3. 安装依赖包                    │   │
│  │ 4. 启动 MySQL 容器               │   │
│  │ 5. 运行测试                      │   │
│  │ 6. 生成测试报告                  │   │
│  └─────────────────────────────────┘   │
│                                         │
│  虚拟机在测试完成后自动销毁              │
└─────────────────────────────────────────┘
```

### 环境配置

```yaml
runs-on: ubuntu-latest  # 使用最新的 Ubuntu 虚拟机

services:
  mysql:                # 启动 MySQL 8.0 容器
    image: mysql:8.0
    env:
      MYSQL_ROOT_PASSWORD: test_password
      MYSQL_DATABASE: image_classifier_test
    ports:
      - 3306:3306
```

**关键点**:
- ✅ 每次测试都在**全新的虚拟机**上运行
- ✅ 测试环境与生产环境**隔离**
- ✅ 测试完成后虚拟机**自动销毁**
- ✅ 使用 Docker 容器提供 MySQL 服务

## 🔍 测试配置详解

### GitHub Actions 配置

```yaml
# .github/workflows/ci-cd.yml

jobs:
  test:
    runs-on: ubuntu-latest  # 运行环境
    
    services:
      mysql:                # MySQL 服务容器
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: test_password
          MYSQL_DATABASE: image_classifier_test
        ports:
          - 3306:3306
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4  # 检出代码
      
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.8'  # Python 版本
      
      - name: Install dependencies
        run: |
          pip install -r requirements.txt
          pip install pytest pytest-cov pytest-asyncio
      
      - name: Run tests
        env:
          MYSQL_HOST: localhost
          MYSQL_PORT: 3306
          MYSQL_USER: root
          MYSQL_PASSWORD: test_password
          MYSQL_DATABASE: image_classifier_test
        run: |
          pytest tests/ -v --cov=app --cov-report=xml
```

### pytest 配置

```ini
# pytest.ini

[pytest]
testpaths = tests              # 测试目录
python_files = test_*.py       # 测试文件模式
python_classes = Test*         # 测试类模式
python_functions = test_*      # 测试函数模式

addopts = 
    -v                          # 详细输出
    --cov=app                   # 代码覆盖率
    --cov-report=term-missing   # 终端报告
    --cov-report=xml            # XML 报告
    --cov-report=html           # HTML 报告
    --asyncio-mode=auto         # 异步测试模式
```

### 如何添加更多测试

#### 示例 1: API 测试

创建 `tests/test_classify.py`:

```python
"""
图片分类 API 测试
"""
import pytest
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_classify_endpoint_exists():
    """测试分类接口是否存在"""
    # 测试接口是否存在（不实际调用，避免需要真实图片）
    response = client.post("/api/v1/classify")
    # 应该返回 422 (缺少参数) 而不是 404 (接口不存在)
    assert response.status_code in [422, 400]

def test_classify_without_auth():
    """测试未认证的请求"""
    response = client.post("/api/v1/classify")
    # 应该返回错误（缺少认证或参数）
    assert response.status_code != 200
```

#### 示例 2: 数据库测试

创建 `tests/test_database.py`:

```python
"""
数据库连接测试
"""
import pytest
from app.database import db

@pytest.mark.asyncio
async def test_database_connection():
```

## 🎯 测试类型

### 1. 单元测试 (Unit Tests)

测试单个函数或方法：

```python
def test_hash_function():
    """测试哈希函数"""
    result = calculate_hash("test")
    assert result == "expected_hash"
```

### 2. 集成测试 (Integration Tests)

测试多个组件协作：

```python
def test_api_with_database():
    """测试 API 与数据库的集成"""
    # 测试完整的请求流程
    response = client.post("/api/v1/classify", ...)
    # 验证数据库中的数据
    assert database_has_record(...)
```

### 3. 端到端测试 (E2E Tests)

测试完整流程：

```python
def test_classify_workflow():

    # 2. 调用分类 API
```

## 🔧 测试最佳实践

### 1. 测试独立性

每个测试应该独立运行，不依赖其他测试：

```python
# ✅ 好的做法
def test_a():
    # 不依赖其他测试
    pass

def test_b():
    # 不依赖 test_a
    pass

# ❌ 不好的做法
def test_a():
    global_var = "value"

def test_b():
    # 依赖 test_a 设置的 global_var
    assert global_var == "value"
```

### 2. 使用 Fixtures

```python
import pytest
from fastapi.testclient import TestClient
from app.main import app

@pytest.fixture
def client():
    """测试客户端 fixture"""
    return TestClient(app)

def test_with_fixture(client):
    """使用 fixture"""
    response = client.get("/api/v1/health")
    assert response.status_code == 200
```

### 3. 测试数据隔离

```python
@pytest.fixture
def test_db():
    """测试数据库 fixture"""
    # 创建测试数据库
    db = create_test_database()
    yield db
    # 清理
    db.drop()

def test_with_clean_db(test_db):
    """使用干净的测试数据库"""
    # 测试代码
    pass
```

### 4. 模拟外部依赖

```python
from unittest.mock import patch

def test_with_mock():
    """使用 mock 模拟外部 API"""
    with patch('app.services.model_client.call_api') as mock_api:
        mock_api.return_value = {"result": "test"}
        # 测试代码
        result = call_service()
        assert result == "test"
```

## 🚨 常见问题

### Q1: 测试在哪里运行？

**A**: 在 GitHub Actions 提供的 Ubuntu 虚拟机上运行，每次测试都是全新的环境。

### Q2: 测试会访问生产数据库吗？

**A**: 不会。测试使用独立的 MySQL 容器，数据库名为 `image_classifier_test`。

### Q3: 如何添加新的测试？

**A**: 在 `tests/` 目录下创建 `test_*.py` 文件，编写测试函数。

### Q4: 测试失败会阻止部署吗？

**A**: 是的。如果测试失败，部署任务不会执行（因为 `deploy` 任务依赖 `test` 任务）。

### Q5: 可以在本地运行相同的测试吗？

**A**: 可以。使用相同的命令和环境变量即可。

### Q6: 测试需要多长时间？

**A**: 通常 1-5 分钟，取决于测试数量和复杂度。
