# 分类接口颜色本地化方案（V2 原地优化）

本文档描述在**不升级接口版本、不升级客户端**的前提下，将 V2 的颜色改为本地算法实现：分类用无颜色提示词，本地算颜色后**直接写入同一条缓存 value**，复用 `llm_inference_cache_v2`，无需新表或新 prompt。

## 1. 背景与目标

- **现状**：分类用 `llm_service.classify_image()`，一次返回内容 + 背景颜色，内容缓存 key 为 image_hash + 提示词（+ model 等）。
- **目标**：
  - **客户端零改动**：仍请求 `/api/v2/classify/*`，请求/响应格式不变。
  - **大模型不再算颜色**：新请求用「无颜色」提示词只做内容分类；老缓存里已有大模型颜色的继续用，不丢。
  - **颜色本地算并复用现有缓存**：在无颜色提示词对应的缓存 value 里**增加 background_color 字段**，不新增表或 key。

## 2. config.py 提示词现状与补齐

当前 `app/config.py` 中与分类/颜色相关的提示词：

| 配置项 | 用途 | 说明 |
|--------|------|------|
| **CLASSIFICATION_PROMPT** | 图片分类（内容 + 颜色） | 要求返回 category、confidence、description、**background_color**，即「有颜色」提示词。 |
| **COLOR_CLASSIFICATION_PROMPT** | 仅颜色分类 | 只要求返回 background_color、confidence，用于单独颜色任务，**不是**「仅内容、无颜色」的分类提示词。 |

因此**没有**「仅内容、无颜色」的分类提示词，需要新增：

- **CLASSIFICATION_PROMPT_CONTENT_ONLY**：与 `CLASSIFICATION_PROMPT` 同结构，但去掉「同时，请识别照片背景的主要颜色…」及 JSON 中的 `background_color` 字段，只要求 category、confidence、description。

## 3. 整体思路

- **内容缓存**：复用 `llm_inference_cache_v2`，key 为 prompt_hash + image_hash + model 等。无颜色 / 有颜色两种提示词对应不同 prompt_hash，可分别命中。
- **_classify_single_image（batch 单张）**：保持单一流程，只用**无颜色提示词**调用 `llm_service.classify_image`。拿到内容后，用本地算法算主色，将 `background_color` **合并进该条缓存的 value** 并写回（即更新同一条记录，不新增 key）。返回内容 + 本地颜色。
- **batch-check-cache**：实现**双提示词查询**。先用有颜色提示词查，命中则直接用（含大模型颜色）；再用无颜色提示词查，命中则解析结果中已含 `background_color`（分类时已写入同一条 value）；都未命中则 cached=False。

颜色不单独缓存，直接存在无颜色提示词对应缓存条目的 value 里。

## 4. 实现步骤（仅服务端）

### 4.1 config.py：新增无颜色分类提示词

- 新增 `CLASSIFICATION_PROMPT_CONTENT_ONLY`（仅内容，无 background_color 要求）。
- 若使用 prompts 目录加载，在映射中增加对应条目（如 `"CLASSIFICATION_PROMPT_CONTENT_ONLY": "classification_content_only"`）。

### 4.2 本地主色模块

- **位置**：`app/services/color_service.py` 或 `app/utils/color_utils.py`。
- **接口**：`get_dominant_color(image_bytes: bytes) -> Optional[str]`，返回 10 个中文之一，与 `model_client.BACKGROUND_COLORS` 一致。
- **实现要点**：PIL 解码、可选缩小 → 转 HSV → 判灰/黑/白 → 色相统计或小 K-means → 映射到 10 标签。

### 4.3 修改 classify_v2.py

- **_classify_single_image**：
  1. 只用**无颜色提示词**调用 `llm_service.classify_image(..., prompt=CLASSIFICATION_PROMPT_CONTENT_ONLY)`，拿到 parsed_result（无 background_color）。
  2. `local_color = get_dominant_color(image_bytes)`。
  3. **更新该条缓存**：将 `background_color: local_color` 合并进 result，调用 `unified_llm_cache.save_result` 写回同一条记录（同一 prompt、image_hash、provider、model_id）。需先读取当前 result，合并后再保存。
  4. `parsed_result["background_color"] = local_color`，构造返回。

- **batch-check-cache**：实现双提示词查询逻辑。
  1. 先用**有颜色提示词**查 `llm_service.check_cache(prompt=CLASSIFICATION_PROMPT, image_hash=...)`。若命中 → 解析结果已含 background_color，直接使用。
  2. 若未命中，再用**无颜色提示词**查 `llm_service.check_cache(prompt=CLASSIFICATION_PROMPT_CONTENT_ONLY, image_hash=...)`。若命中 → 解析结果中已有 background_color（分类时已写入），直接使用。
  3. 都未命中 → cached=False。

无需新增颜色缓存表或 `classify_color` 等新 prompt。

## 5. 缓存说明

- **复用 llm_inference_cache_v2**：不新增表。
- **无颜色提示词 key**：对应条目的 value（model_results 中该 model_key 的 result）在分类完成后会包含 `background_color` 字段。即：`{"category":"...", "confidence":0.9, "description":"...", "background_color":"蓝色"}`。
- **有颜色提示词 key**：老数据，result 中已含大模型返回的 background_color，继续沿用。
- **更新方式**：在 `_classify_single_image` 中算完本地颜色后，读取当前缓存 result，合并 `background_color`，再调用 `unified_llm_cache.save_result` 覆盖同一条记录（同一 prompt、image_hash、provider、model_id）。

## 6. 小结

| 步骤 | 内容 |
|------|------|
| 1 | config.py 新增 `CLASSIFICATION_PROMPT_CONTENT_ONLY`（仅内容）。 |
| 2 | 新建本地主色模块 `get_dominant_color(image_bytes)`。 |
| 3 | _classify_single_image：无颜色提示词 → 拿内容 → 本地算颜色 → **更新同条缓存 value 增加 background_color** → 返回。 |
| 4 | batch-check-cache：双提示词查询（先有颜色、后无颜色）；命中任一则解析结果中已有 background_color，无需单独查颜色。 |

客户端无升级、接口无版本变更；颜色直接写入无颜色提示词对应缓存的 value，复用 `llm_inference_cache_v2`，无需新表或新 key。
