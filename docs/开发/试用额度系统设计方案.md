# 试用额度系统设计方案

## 需求
允许用户不关注公众号即可试用修图功能，但需要控制试用次数，引导用户关注公众号。

## 方案设计

### 1. 数据库设计

创建 `trial_credits` 表：

```sql
CREATE TABLE IF NOT EXISTS `trial_credits` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `client_id` VARCHAR(64) NOT NULL COMMENT '客户端ID',
  `total_trial_credits` INT UNSIGNED DEFAULT 5 COMMENT '试用总额度（默认5张）',
  `used_trial_credits` INT UNSIGNED DEFAULT 0 COMMENT '已使用试用额度',
  `remaining_trial_credits` INT UNSIGNED DEFAULT 5 COMMENT '剩余试用额度',
  `first_used_at` TIMESTAMP NULL DEFAULT NULL COMMENT '首次使用时间',
  `last_used_at` TIMESTAMP NULL DEFAULT NULL COMMENT '最后使用时间',
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_client_id` (`client_id`),
  KEY `idx_last_used` (`last_used_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='试用额度表';
```

### 3. API 层修改

修改 `image_edit_v2.py`：

1. **提交任务时**：
   - 如果没有 `openid`，检查 `client_id` 的试用额度
   - 如果有试用额度，允许提交
   - 如果没有试用额度，提示关注公众号

2. **任务完成时**：
   - 如果没有 `openid`，扣减试用额度
   - 记录试用额度使用日志

### 4. 额度检查逻辑

```
if openid:
    # 检查正式额度（wechat_users表）
    check_and_deduct_credit(openid)
elif client_id:
    # 检查试用额度（trial_credits表）
    check_and_deduct_trial_credit(client_id)
else:
    # 无身份信息，拒绝请求
    raise HTTPException(400, "需要登录或提供client_id")
```

### 5. 用户体验流程

1. **首次使用**：
   - 用户打开应用，获得 `client_id`
   - 首次调用修图API时，自动创建试用额度（5张）
   - 可以使用5张免费额度

2. **试用额度用完**：
   - 提示："试用额度已用完，关注公众号可获得更多额度"
   - 引导用户关注公众号

3. **关注公众号后**：
   - 用户关注公众号，获得 `openid`
   - 系统自动将试用额度转换为正式额度（可选）
   - 或直接使用正式额度系统

## 实现细节

### 试用额度初始化
- 首次使用时自动创建，无需手动初始化
- 使用 `INSERT ... ON DUPLICATE KEY UPDATE` 确保幂等性

### 额度扣减时机
- 提交时：检查额度（不扣减）
- 完成时：扣减实际使用的额度（API调用数，不包括缓存命中）

### 额度合并策略（可选）
- 当用户关注公众号后，可以将剩余的试用额度合并到正式额度
- 或直接清零试用额度，使用正式额度系统

## 配置项

```python
# app/config.py
TRIAL_CREDITS_DEFAULT = 5  # 默认试用额度
TRIAL_CREDITS_ENABLED = True  # 是否启用试用额度功能
```

## 注意事项

1. **防止滥用**：
   - 每个 `client_id` 只能获得一次试用额度
   - 可以考虑结合 IP 地址限制

2. **数据一致性**：
   - 试用额度扣减需要事务保证
   - 任务失败时需要回退额度（可选）

3. **统计需求**：
   - 需要区分试用用户和正式用户
   - 统计试用转化率

4. **用户体验**：
   - 明确提示剩余试用额度
   - 额度用完时引导关注公众号
